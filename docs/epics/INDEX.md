the original spec text), but per the user's 2026-08-22 standing instruction every epic doc still gets
renumbered into this one canonical sequence — there is no longer a "GitHub-Issue-sourced, non-canonical
naming" exception. If a new epic doc/PR ever lands under an old-style (`EPIC-M1.x`/`M3.x`) or ad hoc
(`EPIC-<NAME>-NNNN`) name, rename it into this sequence (next number, update its header, add a row here)
rather than leaving the mismatch.

## What changed in the 2026-08-22 renumbering

- **169 canonical epics** (`EPIC-001` … `EPIC-169`), ordered by each epic doc's true first-commit date, not by
  the old ad-hoc `M1.x`/`M2.x`/`M3.x` numbers (which were assigned independently by multiple concurrent agents
  and had collided/drifted).
- **14 stale duplicate/superseded drafts were deleted** (not archived, per explicit user decision): 10 epic
  numbers (old `M1.73/74/75/79/80/82/84/87/88/89`) each had an early `READY_FOR_APPROVAL` draft that was later
  rewritten to `DONE` under a *different* filename instead of overwriting the original — only the `DONE`
  version survived. `EPIC-M2.1/M2.2/M2.3` were explicitly marked `SUPERSEDED BY M3.1` in their own text and
  were deleted outright.
- **`EPIC-M1.132`-`M1.148` (the original split UI+API track) and `EPIC-M3.1`-`M3.15` (a later renumbering of
  the same scope that the team kept extending for real afterward) were both kept as distinct canonical
  entries**, per explicit user decision -- they are NOT merged/deduplicated against each other even though
  they cover overlapping capability areas.
- **`docs/epics/EPIC-M3-ROADMAP-NOTE.md`** (a roadmap index, not an epic) and
  **`docs/orchestration/EPIC-ORCHESTRATION-POLICY.md`** (a policy doc) were left as-is -- out of scope for
  epic renumbering.
- **Scope of the rename: `docs/epics/*.md` + top-level cross-references (`README.md`, `AGENTS.md`,
  `docs/orchestration/*.md`) only.** Source-code comments/docstrings that mention old EPIC IDs (e.g.
  `EPIC-M1.146`, `EPIC-M3.12`) were intentionally left untouched, per explicit user decision -- a much larger,
  separate sweep across the whole codebase.
